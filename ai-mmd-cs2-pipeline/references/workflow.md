# MMD → CS2 制作和部署详细流程

执行具体模型时先读取 `SKILL.md` 的用户选择与优先级，再按模型和当前游戏版本执行。每阶段保存独立副本与日志；失败时回到对应阶段修复并复检，不将待验证状态标作成功。检测矩阵和交付见 `qa-and-delivery.md`。

## 1. 接收与环境检查

1. 清点 PMX/PMD、纹理、配套动作、说明和许可。记录目录、缺失贴图、使用限制和 SHA-256；保留原件只读，根据许可决定能否打包依赖。不得从受保护的运行时包绕过保护提取内容。
2. 创建独立项目目录：`source/` 原件索引、`work/` Blender 版本、`exports/tp/`、`exports/fp/`、`content/`、`game/`、`reports/`、`evidence/`、`backup/`。用户已有工程时尊重其结构，不覆盖同名成果。
3. 检查 Blender、PMX/PMD 导入器、CS2、Workshop Tools/ModelDoc、资源编译器、动画/武器参考和本地私房加载工具。记录实际版本、可执行文件、项目路径及日志；历史路径、节点名、插件 API 和脚本均需在本机验证。
4. 检查导入器对日文骨名、IK、附加变换、形态键、材质、刚体和关节的支持。导入报错或丢失时记录并尝试可用替代方法；不要把 Blender 约束或 MMD 物理直接当作 Source 2 原生功能。
5. AI 自行编写或调整项目专用脚本、运行 Blender 后台/界面操作、读取日志和截图，并保留脚本及输入输出。工具不可用时说明阻塞，不能宣称已经执行。

## 2. 建立源模型基线

1. 不改变原文件，导入并保存 `source_baseline.blend`。记录导入比例、上轴、单位、对象矩阵、Armature 世界变换及转换顺序。先检查外观，记录原有破面、分离衣片和预期开口，避免误判。
2. 导出骨架清单：原名、唯一 ID、父子关系、头尾、长度、局部轴、rest 矩阵、约束、IK、附加旋转/位移、顶点组和权重。标明主体、手指、面部、衣服、头发、装饰、控制和未分类骨。不得只保留人形关键骨而丢弃原有装饰骨。
3. 导出网格及材质清单：顶点/面、边界与非流形边、松散点、重叠面、法线、UV、材质槽、贴图路径、权重和形态键。保存正背侧及关键局部基线截图，选择可比较的初始姿势。
4. 记录身体关节中心、各骨段长度和左右关系、重要顶点到关节的距离及权重。后续对比允许整体等比例缩放和坐标系转换，不以世界绝对坐标直接判定变化。

## 3. 用户选择高度与统一缩放

执行制作前询问并记录用户选择：① 人形主体接近本机当前默认探员主体高度；② 用户指定主体目标高度和单位；③ 指定全模型统一缩放倍数；④ 保持原主体高度。未选择时可清点环境和建立基线，但不得替用户确定最终高度。

1. 明确主体与装饰：头发、帽子、角、翅膀、饰物、背包和外挂武器不计主体高度；特殊身体结构结合源模型判断并记录。分类保存成对象列表或面集合，混合网格不能直接用整对象包围盒冒充主体高度。
2. 在同一单位、上轴和中性姿势下测量主体脚底至头顶。方案①从本机可读取的当前探员资源按同一规则实测；记录资源、姿势、选区与值，无法获取时阻塞该方案，不猜官方数值。方案②统一单位后以 `目标主体高度 / 源主体高度` 算倍率；③采用用户倍数；④倍率为 1。记录原值、目标、倍率和误差。
3. 将主体、骨架、装饰和挂点作为整体统一 XYZ 缩放；不得单独缩放腿、手臂或骨骼来迁就探员。变换前后对比相对比例、网格与骨架关系，检查动画、约束、物理尺寸和导出是否重复缩放。另记录包含装饰的静态及动态包围盒。
4. 高度选择改变后重新测量，审计比例、动作和 bounds，并重新导出、编译及实机验证；旧结果不可套用。

## 4. 清理、权重与局部修复

1. 在副本检查无权重、总和异常、错误左右骨、离群权重和引擎允许的影响骨数量。定位异常并比较基线，保守归一化或局部重分配；不要全身自动重绑。记录每次修改对象、顶点、骨和前后数值。
2. 检查边界、接缝、重叠、翻面、退化面和法线。结合源图、UV、材质、位置及动态动作辨别预期开口和真破洞；本来独立的衣层不强行焊接。修复时保留轮廓、UV、材质、法线和权重，比较前后截图，并在关节弯曲及极限动作中检查裂口和穿模。
3. 检查主体、头发、衣服、裙摆和饰品的随动；保留原辅助骨与层级，检查骨链及权重。MMD 刚体、关节、重力和弹簧可能没有一对一对应：依据当前引擎能力实现次级运动，记录保留、近似、禁用和待验证部分；死亡 ragdoll 单独处理。
4. 对比修复版与基线骨架、比例及网格。兼容性所需的重命名或局部修正要有映射、理由和可回滚副本；禁止将官方关节位置或骨长写回原模型迫使其对齐。

## 5. 保留原骨的动画适配

1. 从本机可用玩家、动画、视模和武器资源建立参考，检查许可及版本。建立语义映射表：参考骨、源骨、父级、左右、局部轴、rest 方向、允许旋转/位移和辅助骨；同名不代表骨轴或语义相同。
2. 保留源变形骨的 rest 层级及骨长，优先在独立控制骨/驱动层接收目标动画，计算姿态空间偏移将旋转传给源骨。考虑根运动、坐标系、肩臂扭转、足部方向、手指、IK 和烘焙；不要直接复制官方世界位置给源关节。装饰骨按源权重和可用次级运动单独驱动。
3. 在 Blender 验证基准姿势及少量动作，再导出并验证当前 ModelDoc/动画图实际支持此结构。若引擎要求额外命名、驱动骨或层级，保留源骨并区分兼容层与变形层；若编译或运行无法实现，记录限制，不能称为已兼容。
4. 以旋转、可控 IK、武器挂点偏移和动作修正求解握枪接触，限制肘腕和手指异常；不可达时报告及保留证据，不拉长手臂或移动原始关节。按检测矩阵扫描全身及局部，记录动作名、帧与部位，修复后重跑。

## 6. 独立制作第一人称手模

1. 从源模型或可追溯的未破坏副本复制双手、前臂、衣袖/手套及材质到独立工程。记录源对象、顶点来源和基线；第三人称工程保持独立。不要把官方手直接替换为成品，或将完整第三人称模型误称为独立视模。
2. 依据实际相机与视模参考确定保留范围，处理袖口切口、遮挡和法线/UV/权重过渡；避免镜头看到开口或手臂凭空消失。保留原手型、指节、相对长度和外观，不因官方手骨长度调整手形。
3. 单独建立 FP 控制骨及动画映射，适配实际左右手、武器动画、附件和视角。按枪柄、扳机、护木分别检查手掌手指；刀具、步枪、手枪及其他本机可用类别分别检查。变更 FP 后单独导出、更新引用并验证哈希；TP 的验证不能代表 FP。

## 7. 导出、编译与依赖

1. 分别保存可编辑 TP/FP 工程并导出。记录坐标轴、单位、骨架及动作选择、路径、时间和哈希；检查重新导入后的比例、骨架、权重、材质及动画，避免仍引用旧 FBX。
2. 按当前支持的 ModelDoc/资源格式连接 TP/FP、材质、贴图、动作、动画图、附件及物理。检查骨数、影响数、命名和路径的实际限制，不能把历史数值或示例节点视为保证。
3. 根据角色外形和实际游戏行为配置碰撞、hitbox 与死亡物理；区分静态 bounds、动画动态 bounds、碰撞和 hitbox，单独验证。编译后核对退出码、日志、警告、产物位置、时间、哈希及依赖闭包；编译通过不等于挂载、换模或动作通过。

## 8. 本地部署与验证

1. 选择用户授权的本机私人测试环境，检查游戏版本、资源路径、实际可用挂载/换模机制及插件兼容性。列出将改动的文件，备份原配置和哈希，保存恢复步骤；不要覆盖官方 VPK、核心模型或修改反作弊机制。`sv_cheats`、局域网和启动参数本身不保证资源加载。
2. 部署当前产物并核对磁盘哈希、依赖和加载日志，确认资源挂载与预缓存；针对本机玩家 Pawn 实际换模并确认 TP，再验证 FP 确实切换。bot 可辅助观察，但只给 bot 换模不能替代本机玩家通过。
3. 在本地房运行检测矩阵，覆盖持枪、运动、死亡/复活、双视角和装饰动态。保存可识别模型版本、武器、动作及场景的截图/视频和日志，复现异常记录帧或时间。发现缺陷后修复、重新导出编译部署并重跑受影响项目。
4. 缺少可用挂载或 FP 切换机制时，将该项记为 PENDING/BLOCKED，报告尝试、错误、受影响功能和后续条件；禁止以静态截图、编译成功或旧日志冒充当前实机结果。提供可验证的部署和回滚说明。
